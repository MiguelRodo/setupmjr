agent

Use the agent command for user-level coding-agent configuration. Provider setup belongs here; pj only launches already-configured agents.

Inspect agent configuration

Show the effective Codex provider and configured opt-in subagent:

setupmjr agent --config

List the available choices and short aliases:

setupmjr agent --list

Running setupmjr agent without options prints command help.

Configure model-provider authentication

Configure the DeepSeek endpoint once for agent clients:

setupmjr agent --auth deepseek
# short form
setupmjr agent -a d

The command reuses DEEPSEEK_API_KEY when it is already set, then checks the managed DeepSeek credential and existing Codex DeepSeek configurations. If no key is available, it prompts for one without echoing it.

The reusable key is stored at:

~/.config/setupmjr/agent/auth/deepseek.key

with private permissions. This credential is also discoverable by the Codex DeepSeek setup, so a key entered for Copilot can be reused when switching Codex to DeepSeek later.

For Copilot CLI, --auth deepseek writes a managed environment at:

~/.config/setupmjr/agent/copilot.env

and sources it from Bash and Zsh startup files. It configures DeepSeek’s documented Copilot BYOK path:

COPILOT_PROVIDER_TYPE=anthropic
COPILOT_PROVIDER_BASE_URL=https://api.deepseek.com/anthropic
COPILOT_MODEL=deepseek-v4-pro
COPILOT_PROVIDER_MAX_PROMPT_TOKENS=840000
COPILOT_PROVIDER_MAX_OUTPUT_TOKENS=128000

The API key itself is not duplicated in the shell startup files. Restart the shell, or source the managed environment directly, before starting Copilot.

DeepSeek BYOK does not itself sign Copilot into GitHub. If you want GitHub-hosted features such as remote control, authenticate Copilot with GitHub separately (for example, copilot login) while keeping the DeepSeek BYOK environment active.

At present deepseek is the only managed --auth endpoint. The endpoint argument is explicit so additional providers can be added without changing the command shape.

Switch the primary Codex provider

OpenAI/ChatGPT is the default value for -c, so these are equivalent:

setupmjr agent -c
setupmjr agent -c o
setupmjr agent --codex-provider openai

Switch Codex to DeepSeek:

setupmjr agent -c d
setupmjr agent --codex-provider deepseek

The first DeepSeek setup uses DeepSeek’s official Codex setup script and selects the Flash model. setupmjr reads DEEPSEEK_API_KEY when it is set, reuses a key from an existing managed DeepSeek configuration when possible, or prompts for the key without echoing it.

Before changing provider, setupmjr stores private snapshots of the active Codex config.toml and models.json under:

~/.config/setupmjr/agent/codex/

After both providers have been seen once, -c d and -c o switch by restoring those snapshots rather than rerunning the full DeepSeek installer.

If DeepSeek was already installed manually with the official setup script before setupmjr started managing providers, the first switch back to OpenAI uses DeepSeek’s official restore path once and then records the restored OpenAI state. Later switches are local snapshot restores.

Provider changes affect the ordinary Codex home at ~/.codex, so they apply to Codex clients that share that configuration. Restart active Codex clients after switching. A DeepSeek session may have logged Codex out of ChatGPT, so restoring the OpenAI configuration does not guarantee that the ChatGPT account is still authenticated.

The automated DeepSeek bootstrap currently requires Bash and curl, and is intended for Linux, macOS and WSL environments.

Configure an opt-in subagent

agy is the default value for -s:

setupmjr agent -s
setupmjr agent -s agy
setupmjr agent --subagent agy

This installs the bounded Codex guidance and narrow execution rule for delegating explicitly authorised work to Gemini through agy. Existing Codex instructions outside the managed block are preserved.

To use DeepSeek instead:

setupmjr agent -s deepseek

The DeepSeek subagent uses an isolated Codex home:

~/.codex-deepseek-subagent

It does not change the primary Codex provider. The managed guidance invokes the worker with codex exec --sandbox workspace-write and the isolated CODEX_HOME. As with agy, delegation remains opt-in: Codex may use the subagent only when you explicitly authorise it for the current task or conversation.

Selecting one subagent replaces the managed configuration for the other. --subagent-agy remains as a deprecated compatibility alias for --subagent agy.

Credential storage

setupmjr agent --auth deepseek stores the reusable DeepSeek API key in ~/.config/setupmjr/agent/auth/deepseek.key with private permissions. Copilot’s managed environment reads that file at shell startup rather than embedding the key in .bashrc or .zshrc.

DeepSeek’s official Codex format also stores the API key in config.toml. The saved DeepSeek provider snapshot therefore contains that key as well. setupmjr creates its provider-state directories with mode 0700 and writes credential and snapshot files with mode 0600. Treat these files as credentials and do not commit or share them.
