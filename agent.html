agent

Use setupmjr agent for user-level coding-agent configuration. pj launches already-configured agents; provider and credential setup belongs here.

Install all three CLIs with setupmjr install agents (see installation). It uses the existing native vendor installers, skips CLIs already on PATH, and leaves authentication, API credentials and configured model providers unchanged.

Run setupmjr agent --help for authoritative option syntax and setupmjr agent --list for accepted endpoints, providers, subagents and aliases.

Inspect configuration

setupmjr agent --config
setupmjr agent --list

--config reports the effective Codex provider, Copilot provider and configured opt-in subagent. Running setupmjr agent without options prints command help.

Update installed CLIs

setupmjr agent update claude
setupmjr agent update codex
setupmjr agent update copilot
setupmjr agent update --all

Choose one agent or --all; these selectors cannot be combined with provider or authentication options. Updates use the first matching executable on PATH. With --all, missing tools are reported as skipped; a missing single selection is an error. Every installed tool is attempted even if another fails, with a separate completion or failure line for each tool and a nonzero exit status if any failed. Vendor output reports whether a version changed or was already current; completion means the update command succeeded.

Installed method Update path
Native Claude, Codex or Copilot on Linux, macOS, WSL or Windows The installed CLI’s update command, after checking its help advertises that command
Homebrew executable resolving into Caskroom or Cellar brew upgrade --cask <installed-package> or brew upgrade --formula <installed-package>
Claude or Copilot resolving into a Windows WinGet package directory winget upgrade --id <installed-package> --exact --source winget
Detected npm/shim, system /usr/bin or /bin, or Nix installation Report an error directing you to the original package manager

Homebrew package suffixes and Copilot’s WinGet prerelease package are retained. An installed package manager must be on PATH. Other custom wrappers or install layouts may not reveal their package manager; native update support and installation handling are then delegated to the vendor. Older CLIs without an advertised update command require a one-time update through their original installer or package manager. setupmjr does not automatically migrate them to another installation method.

An explicit update requests a manual check even when background updates are available. Existing auto-update settings, environment variables and release-channel configuration are passed through. setupmjr does not rewrite provider configuration, sign-in state, credentials or shell startup files. Vendor updaters may use the network, request permissions, and require running agent sessions to be restarted. On WSL, use the Linux setupmjr and Linux agents. Platforms other than Linux, macOS and Windows are rejected.

See the official Claude update documentation, Codex command reference, and Copilot command reference.

Diagnose installations

setupmjr agent doctor

Doctor checks Claude Code (claude), Codex (codex) and GitHub Copilot CLI (copilot) on the current process’s PATH. It prints the selected executable locations, versions and setupmjr-managed provider/subagent configuration, then continues through all checks with actionable fixes. It exits 0 when no checks fail and 1 when any check fails, including a missing CLI. WARN means unverified and does not change the exit status. Extra options are rejected; doctor cannot be combined with setup actions.

Checks are read-only: doctor never installs, updates, signs in, sources shell files or writes configuration. It invokes only --version, Claude’s auth status and Codex’s login status, with closed stdin and a ten-second timeout per probe. Raw command output and errors are suppressed; only version numbers and credential-presence/status summaries are displayed. It makes no inference requests or deliberate credential-validation network requests. Local credential presence does not establish validity, account entitlement or service connectivity.

Copilot authentication may live in an OS credential store. Doctor does not inspect that store or launch an interactive session: it reports authentication as unverified when no token environment variable is available. It checks COPILOT_GITHUB_TOKEN, GH_TOKEN and GITHUB_TOKEN in precedence order for empty values and unsupported classic PATs, without printing their values. Provider API keys are reported as present but unvalidated. To resolve access problems, run copilot login yourself.

Managed DeepSeek checks detect missing credentials, an inactive Copilot shell environment and incomplete isolated subagent configuration. An opted-in agy subagent must be on PATH; its authentication remains unverified. CODEX_HOME is honored by the Codex checks and produces a warning because it can override setupmjr’s configuration in ~/.codex. Custom providers, CLI-specific configuration overrides and credential helpers may need separate investigation.

Platform details:

  • Ubuntu/Linux and WSL: PATH checks describe the current Linux environment. A Windows installation does not establish that the Linux CLI is available in WSL; run the Linux setupmjr executable there.
  • macOS: the same CLI status commands support credentials stored through vendor mechanisms, including Keychain; doctor does not assume that a missing plaintext credential file means signed out.
  • Native Windows: lookup uses Windows PATH/PATHEXT. Doctor probes native executables directly; .cmd/.bat shims produce an actionable failure asking for the native installation. Claude Code needs Git for Windows (Git Bash). Bash/Zsh exports do not configure PowerShell; configure custom provider variables in the shell that launches Copilot.

Store DeepSeek authentication

setupmjr agent --auth deepseek
setupmjr agent -a d

Authentication is credential-only: it does not change the active Codex or Copilot provider.

setupmjr reuses DEEPSEEK_API_KEY when available, then checks its managed credential and existing Codex DeepSeek configuration, and otherwise prompts without echoing the key. The reusable credential is stored at:

~/.config/setupmjr/agent/auth/deepseek.key

The file is private and can be reused by both managed DeepSeek provider paths. DeepSeek is currently the only managed --auth endpoint.

Copilot provider

GitHub-managed Copilot models are the default value for -p:

setupmjr agent -p
setupmjr agent -p g
setupmjr agent --copilot-provider github

Switch to DeepSeek after storing its credential:

setupmjr agent --auth deepseek
setupmjr agent -p d

The managed environment lives at ~/.config/setupmjr/agent/copilot.env and is sourced by Bash and Zsh startup files. DeepSeek uses its Anthropic-compatible endpoint with the Flash model; COPILOT_PROVIDER_TYPE=anthropic selects the wire protocol, not Anthropic as the model vendor.

The raw key is not embedded in the provider environment. Switching back to github removes the managed BYOK provider variables for new shells. Restart the shell, or source the managed environment file, after switching. GitHub authentication for Copilot remains separate from provider selection.

Codex provider

OpenAI/ChatGPT is the default value for -c:

setupmjr agent -c
setupmjr agent -c o
setupmjr agent --codex-provider openai

Switch to DeepSeek with:

setupmjr agent -c d
setupmjr agent --codex-provider deepseek

The first managed DeepSeek setup uses DeepSeek’s official Codex setup script and selects the Flash model. setupmjr stages that script with its bounded downloader and runs it with bash --noprofile --norc plus a reduced environment. A timeout, failed HTTP response or incomplete download prevents execution.

This remains a remote-code trust boundary: DeepSeek publishes the installer at a mutable CDN URL without a versioned script or checksum that setupmjr can pin. If you do not want to run the vendor script, use DeepSeek’s documented manual Codex setup instead: https://api-docs.deepseek.com/quick_start/agent_integrations/codex/.

Before provider changes, setupmjr snapshots the active Codex config.toml and models.json under:

~/.config/setupmjr/agent/codex/

After both providers have been seen once, switching restores local snapshots instead of rerunning the DeepSeek installer. A pre-existing manual DeepSeek installation uses the vendor restore path once to capture the OpenAI state.

Provider changes affect the ordinary ~/.codex home. Restart active Codex clients after switching. Restoring OpenAI configuration does not itself restore a ChatGPT login that a previous DeepSeek session may have displaced.

The automated DeepSeek bootstrap requires Bash and is intended for Linux, macOS and WSL.

Opt-in subagent

agy is the default value for -s:

setupmjr agent -s
setupmjr agent -s agy
setupmjr agent --subagent agy

This installs bounded Codex guidance for explicitly authorised delegation through agy, preserving instructions outside the managed block.

DeepSeek can be configured instead:

setupmjr agent -s deepseek

The DeepSeek subagent uses the isolated Codex home ~/.codex-deepseek-subagent and does not change the primary Codex provider. Its worker runs through codex exec --sandbox workspace-write. Delegation remains opt-in for the current task or conversation.

Selecting one managed subagent replaces the other. --subagent-agy remains as a deprecated compatibility alias for --subagent agy.

Credential boundaries

setupmjr creates managed agent-state directories with mode 0700 and credential/snapshot files with mode 0600 on POSIX systems. DeepSeek’s Codex config.toml format contains the API key, so DeepSeek snapshots are credentials too. Do not commit or share the managed credential or snapshot files.
